# Версионность Zapret GUI

У проекта **две независимые линии версий** — Windows и macOS. Версии не
сводятся в одну нумерацию: платформы развиваются разными темпами, и общая
нумерация только путает (пример путаницы: qa-2 от 2026-08-21 был про
Windows 0.2.1, хотя mac-линия была на 0.2.1-mac.1).

## Схема

| Платформа | Формат | Где задаётся | Пример |
|---|---|---|---|
| Windows | `MAJOR.MINOR.PATCH.N` | `app.go` → `AppVersion`; PE-метаданные exe — `build/windows/info.json` | `0.2.5.0` |
| macOS | `MAJOR.MINOR.PATCH-mac.N` | `app_darwin.go` → `AppVersion`; `wails.json` → `version` (Info.plist/dmg) | `0.2.2-mac.2` |

`wails.json` → `version` — **mac-поле** (подставляется в `Info.plist`/dmg).
Windows-версия в PE-ресурс exe не из `wails.json`, а из `build/windows/info.json`
(правится при каждом Windows-релизе).

Правила:

- `MAJOR.MINOR` может совпадать у платформ (общая кодовая база фич), а может
  и нет — линии НЕ синхронизируются принудительно.
- `-mac.N` — счётчик mac-сборок в рамках своего PATCH; инкрементируется при
  каждой mac-сборке с изменениями (dmg для друзей — только при изменениях).
- Windows-номер НИКОГДА не содержит суффиксов; mac-номер ВСЕГДА содержит
  `-mac.` — по строке версии всегда ясно, о какой платформе речь.
- PATCH у mac может «обогнать» windows или отстать — это нормально.

## Артефакты сборки

| Платформа | Файл | Пример |
|---|---|---|
| Windows | `dist/ZapretGui-v<версия>.zip` (+ голый `dist/ZapretGui.exe`) | `ZapretGui-v0.2.2.zip` |
| macOS | `dist/ZapretGui-macOS-universal-<версия>.dmg` (собирается на Mac, `bash build-macos.sh`) | `ZapretGui-macOS-universal-0.2.1-mac.1.dmg` |

При релизе для друзей версия в README.txt внутри архива обязана совпадать
с `AppVersion` в бинаре (проверять перед упаковкой).

## Где смотреть текущую версию

- В приложении: чип `gui <версия>` в шапке окна.
- В коде: `AppVersion` в `app.go` (windows) / `app_darwin.go` (darwin).
- В git: windows-релизы — теги `v<версия>` на ветке `master`; mac-релизы —
  теги `v<версия>` на ветке `macos`.
